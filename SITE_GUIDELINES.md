# SITE GUIDELINES

Этот файл нужен как локальная опора для дальнейшей работы по `YourWorld-Guide`.
Если в новом диалоге продолжать редактирование сайта, агент сможет прочитать этот файл и быстрее попасть в текущую систему без повторного долгого согласования.

## Цель сайта

- Дополнительный навык `redesign-existing-projects` используется для проверки читаемости, состояний элементов, отступов и адаптивности. Его авторские предпочтения не заменяют утверждённый пользователем дизайн YourWorld: дымчатое чёрное стекло, тёплый оранжевый акцент, мягкие фоновые градиенты, Rubik и существующие игровые изображения. Не менять эти решения ради требований навыка к плоским фонам, другой палитре или шрифтам. Реальные игровые характеристики не редактировать ради визуальной «правдоподобности» чисел.

- Сайт — это wiki и база знаний по проекту `YourWorld PVE`.
- Основной тон: понятный, игровой, аккуратный.
- Любая новая страница должна выглядеть как часть одной системы, а не как отдельный микросайт.

## Структура файлов

- С 10.11.2026 основная тема — дымчатое чёрное стекло с оранжевыми акцентами.
- На рабочих страницах `body` должен иметь класс `site-glass` (в дополнение к классам раздела).
- После общего и локального CSS подключать `/styles/glass-site.css`: это единый источник поверхностей, кнопок, навигации, модалок и подвала.
- Главная дополнительно использует `home-glass` и `/styles/home-glass.css`.
- Тестовые `index-glass*.html` и их CSS не являются зависимостями рабочего сайта.
- Подробности переноса и восстановления: `GLASS_MIGRATION.md`.

- Общий стиль сайта: [style.css](/c:/Users/Malina/Documents/GitHub/YourWorld-Guide/style.css)
- Локальные стили страниц: `styles/pages/<page>.css`
- Страница должна подключать общий `style.css` и при необходимости свой page-CSS.
- Большие `<style>` внутри HTML не использовать.

## Базовый каркас страницы

Для верхнеуровневых wiki-страниц использовать один и тот же порядок:

1. `page-top` с кнопкой назад
2. `hero` с иконкой страницы, заголовком и коротким описанием
3. основные секции через `card info-card`
4. `site-footer`

## Единый UI-паттерн

### Кнопки

- Для основных действий использовать один визуальный паттерн:
  - фон `rgba(255, 133, 0, 0.08)`
  - бордер `rgba(255, 170, 70, 0.24)`
  - hover `rgba(255, 133, 0, 0.14)`
  - радиус `8px`
  - высота `42px` или `44px`
- Кнопки одинакового смысла должны выглядеть одинаково:
  - `Открыть`
  - `Закрыть`
  - `Возможные награды`
  - кнопки-вкладки
  - кнопки-переходы

### Карточки

- Одежда: рабочая страница `clothing-info/index.html` использует `styles/pages/outfits-glass.css`. Полные сеты сохраняют большую карточку; версии с одним предметом получают `outfit-card--single` и компактное изображение (160–210 px на широком экране). Не задавать рюкзакам и ремням высоту полного персонажа. Категории получения и тип предмета — независимые фильтры. Сортировать по базовому названию через `localeCompare(..., "ru", { numeric: true, sensitivity: "base" })`, без принудительного переноса «Невидимых» предметов в конец. Идентификаторы комплектов должны быть уникальными, включая одинаковые названия в разных категориях.

- Утверждённые компоненты рецептов: `.item-list` — сетка из пяти колонок на широком экране, четырёх до 1000 px, трёх до 780 px и двух до 540 px. Карточки `.item-row` имеют изображение высотой 104 px, название снизу и количество справа сверху. Даже при 1–3 ингредиентах не растягивать карточки на всю ширину.
- Верхняя `.page-top` — единая тёмная стеклянная панель со стрелкой, хлебными крошками и поиском. До 640 px хлебные крошки переходят на вторую строку. Не добавлять `backdrop-filter` на эту панель: она содержит поиск с модальным окном.
- Эти правила находятся в `styles/glass-site.css`; CSS предпросмотров не подключать к рабочим страницам.

- Основные блоки делать через:
  - border `rgba(255,255,255,0.08)`
  - radius `10px` (крупные шапки `12px`, модалки и подвал `14px`)
  - полупрозрачный чёрный фон, тонкая светлая грань и мягкая тень
- Общий фон — затемнённый обесцвеченный игровой лес с мягким оранжевым светом.
- Не добавлять зелёные оттенки, угловые отметки или яркое свечение вокруг каждой картинки.
- Не назначать `backdrop-filter` контейнерам с вложенными fixed-модалками: это меняет их систему позиционирования.
- Внутри карточек соблюдать ровный ритм:
  - заголовок
  - контент
  - пояснение / action

### Модалки

- Все модалки должны иметь:
  - затемнённый backdrop
  - скруглённую панель
  - кнопку `Закрыть` в том же стиле, что и action-кнопки
  - одинаковую логику закрытия по `Esc` и по клику вне панели

### Подписи к изображениям

- Если изображение можно увеличить, подпись должна быть короткой и одинаковой по смыслу:
  - `Нажмите на картинку, чтобы увеличить`
- Если изображение не увеличивается, не добавлять псевдо-подписи “для вида”.

## Текст и формулировки

- Писать по-русски, без канцелярщины и без лишней “технички”.
- Избегать разговорных форм в SEO и официальных описаниях:
  - плохо: `инфой`
  - хорошо: `информацией`
- Формулировки в пределах похожих разделов должны быть едины:
  - `Рекомендуемое оружие`
  - `Возможные награды`
  - `Необходимые предметы`
  - `Как зайти на сервер`

## SEO

Для каждой верхнеуровневой страницы должны быть:

- `title` в формате `Название | YourWorld Wiki`
- `meta description`
- `og:title`
- `og:description`
- `og:image`
- `og:type`
- `og:url`

Описание должно быть коротким, понятным и без сленга.

## Изображения и alt

- Все смысловые `img` должны иметь `alt`.
- `alt` должен описывать содержимое, а не повторять `image` или `photo`.
- Если картинка декоративная, можно оставлять пустой `alt=""`, но только если это действительно декор.

## Мобильная версия

- Верхние блоки и hero-секции обязаны нормально складываться в колонку.
- На мобильных:
  - уменьшать внутренние отступы
  - переводить сложные grid-блоки в 1 колонку
  - длинные кнопки растягивать на всю ширину
  - не оставлять слишком узкие фиксированные колонки
- Особое внимание:
  - главная
  - модалки
  - секции с карточками
  - длинные кнопочные панели

## Перед добавлением новой страницы

Нужно проверить:

- есть ли нормальный `hero`
- есть ли `page CSS` в `styles/pages/`
- есть ли мета-теги
- есть ли alt у изображений
- не выбивается ли страница по кнопкам, карточкам и отступам
- не ломается ли она на мобильной ширине

## Что не делать

- Не плодить новые визуальные паттерны без необходимости.
- Не вставлять большой локальный CSS прямо в HTML.
- Не делать кнопки одного смысла разными по цвету и форме.
- Не использовать разные стили заголовков и карточек на похожих страницах без причины.
